# corpus —— 语料工程

这个目录放的是「人格卡里的数字到底从哪来、怎么验证」的那套工具。

## 为什么它在这里，而不在 `state/`

工具原先在 `state/corpus/`。`state/` 被 `.gitignore` **整目录忽略**，后果是：

- 校验脚本本身从未进版本库 → 换机器、重装、甚至只是 `git clone` 到别处，工具全丢；
- 卡片里的数字依然在，但**再也没有东西能验证它**，而且没有任何报错提示这一点；
- 也就是说，"护栏"和"它守护的东西"分开了：卡片进库，护栏不进库。

护栏静默失效比没有护栏更糟，因为人还以为有。所以工具搬到这里（入库），
原始语料仍留在 `state/corpus/`（不入库，见下方「目录分工」）。

## 目录分工

| 路径 | 是否入库 | 说明 |
| --- | --- | --- |
| `corpus/scripts/` | ✅ | 校验与统计工具。这是本目录存在的理由。 |
| `corpus/out/baseline.json` | ✅ | 语料基线（生成物）。入库是为了能 diff 出「数字哪一轮变了」。 |
| `corpus/out/backup/` | ❌ | 卡片历史快照，含私人语境。 |
| `corpus/data/` | ❌ | 原始语料快照（体积大，且是他站内容）。要用时自行放进来。 |
| `state/corpus/` | ❌ | 运行时采集落盘区（采集器一直在往这儿写，不搬家）。 |

语料读取时**两个目录都扫**（`corpus/data/` + `state/corpus/`），同名以仓库内为准。
这样「拿仓库自带语料复现基线」和「继续采新数据」不冲突。
用环境变量 `QQB_STATE` 可以整体换掉运行时目录（换机只读分析时用）。

## 常用命令

```powershell
# 重建基线（读全部语料 → corpus/out/baseline.json）
node corpus/scripts/baseline.mjs

# 校验卡片数字 vs 实测（定稿期：不符即失败）
node corpus/scripts/verify-numbers.mjs

# 采集期跑：会随语料增长的数值只提示，不判失败
node corpus/scripts/verify-numbers.mjs --collecting

# 把实测值写回卡片（先预演，确认后再 --write）
node corpus/scripts/sync-card-numbers.mjs
node corpus/scripts/sync-card-numbers.mjs --write

# 一次跑全部回归
node corpus/scripts/run-corpus-checks.mjs

# 在 DSH 沙箱内（禁止子进程再起进程，spawn 会 EPERM）：
node corpus/scripts/run-corpus-checks.mjs --no-spawn --quiet
```

## 退出码约定

| 码 | 含义 | 什么时候用 |
| ---: | --- | --- |
| `0` | 通过 | — |
| `1` | **真的失败**（数字不符、口径不一致、代码 bug） | 需要有人去看 |
| `2` | **本机缺数据，跳过** | 干净 clone 没有 `state/corpus` 时的正常状态 |

`2` 这个码不是凑数的。干净 clone 里没有原始语料（`state/` 不入库），
若把「没有数据可验」算成失败，仓库就永远红着；红得没有信息量，
真问题来了也没人看。所以 `run-corpus-checks` 把它显示成 `⏭` 并在结尾
明确写出「跳过不等于通过，这些项在本机没有验证过」——
既不假装通过，也不制造假警报。

## 脚本清单

| 脚本 | 作用 |
| --- | --- |
| `corpus-paths.mjs` | **路径的唯一来源**。语料位置、基线位置、输出目录都从这里取，不要在别处写死盘符。 |
| `spoken-bands.mjs` | **口语档位的唯一来源**（「四成」「六成半」各自覆盖哪一段）。sync 与 verify 共用，避免两套边界打架。 |
| `baseline.mjs` | 从全部语料重算语感基线，输出 `out/baseline.json`。零语料时**拒绝写盘**。 |
| `verify-numbers.mjs` | 校验卡片引用的数字与基线一致。 |
| `sync-card-numbers.mjs` | 把基线实测值写回卡片（幂等，可反复跑）。 |
| `verify-danmaku-baseline.mjs` | 独立复算弹幕指标，核对 baseline 口径（防同一处 bug 自我印证）。 |
| `stability.mjs` | 前后半段稳定性；`--final` 改判「卡片措辞在两半是否都成立」。 |
| `check-example-rewrite.mjs` | 「回复示例」节的空格→逗号改写不会弄坏专名（该节不存在时跳过）。 |
| `test-bili-dedup.mjs` | 采集器去重与翻页自测（含断言自身的判别力验证）。 |
| `run-corpus-checks.mjs` | 统一回归入口。**先重建 baseline，再 sync 卡片，最后校验**。 |
| `migrate-collect-paths.mjs` | 一次性迁移工具（已跑完），把 `collect/` 里的硬编码路径换成 `corpus-paths`。 |

## 两条踩过的坑，写在这里免得重犯

**一、同一个概念只能有一份定义。**
「六成半」曾在 sync 里定义成 66%~72%，在 verify 里写成 60%~70%。
两套边界各自都合理，但从没放在一起对过。实测 71.3% 时，sync 判「落在六成半档」
把卡片写成"六成半"，verify 判「71.3 ≥ 70」当场红了。
根因不是哪个数字错，而是**同一件事有两份定义**。所以现在 `spoken-bands.mjs` 只定义一次。

**二、校验要校验「卡片承诺了什么」，不是「卡片用了哪句话」。**
上一版把断言死死绑在具体措辞上（章节名 `## 十、真实语料`、
「四成在 8 字以内」、「在 N 万条去重语料里」）。人格卡重写后章节改名、
措辞收敛，**18 项断言集体失效**——但它们失效的原因是「卡片换了说法」，
不是「数字错了」（逐项核对过，每个数字都对得上基线）。
所以现在的定位方式是「标题含『语料』或『实测锚点』」，
断言改成在整节里宽松抽取数字；卡片没引用某项时明确记为「跳过」而不是失败。

**三、零输入时最重要的行为是「别输出结论」。**
这一条是拿干净 worktree 当"新人第一次 clone"跑出来的，代价很实在：
- `baseline.mjs` 零语料时**照样写盘**，把好基线换成全零，退出码还是 0；
- `stability.mjs` 零语料时算出"前半 0.0% / 后半 0.0%"，结论是
  「卡片措辞已失效，需改卡片」——**完全错误**，卡片没错，只是没数据；
- `verify-*` 崩在 `Cannot read properties of null`，报错指不到真因。

三个症状不同，病根是同一个：把「没有输入」当成了「输入是不好的值」。
现在的规则是**零输入就停下来说清楚**（拒绝写盘 / 退出码 2），
绝不在零输入上继续算出一个结论——因为错误的结论比没有结论更有害，
它会让下一个人去改一个本来就对的地方。

顺带保住了一条真实数据：差点因为一次冒烟测试，
把版本库里的 `baseline.json` 从 22177 字节清零。

## 加新断言时

问自己两句：

1. **这条断言在卡片没有它引用的东西时，会红吗？**
   如果会，说明它绑定了具体措辞，卡片一重写就会误报。改成
   「卡片提了 → 必须对；卡片没提 → 明确跳过」。

2. **这条断言在没有任何输入时会怎样？**
   如果它会算出一个数（哪怕 0）并据此下结论，就是上面第三条坑。
   改成先检查「有输入吗」，没有就用退出码 2 停下。

反过来，**定性断言**（如「这些词都不到 1%」）不能因为采集期就降级：
它不会随语料长大而自动变真，只会越采越可能变假。
这类用 `verify-numbers.mjs` 里的 `checkStrict`，采集期也判失败。
