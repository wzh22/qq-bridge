# 日记本（Diary）

让 QQ bot 拥有**叙事性长期记忆**：记得更久远的事，换一个新会话后记忆和说话风格仍然保持连续。

## 它和现有记忆功能的区别

项目里已经有三套记忆，日记本是第四套。它们的边界是刻意分开的：

| 模块 | 记的是什么 | 粒度 | 谁写入 | 解决什么 |
|---|---|---|---|---|
| `owner-memory.js` | 关于主人的**事实** | 一句话 | 后台提炼 | 记性准（谁是谁、喜欢什么） |
| `slang-learner.js` | 黑话、网络梗 | 一个词 | 学习任务 | 听得懂群里的说法 |
| `tieba-style` | 语感、口头禅 | 风格片段 | 采语料 | 说话的味道 |
| **`diary.js`** | **发生过什么的叙事** | **一段** | **AI / 手动** | **记性长、人格稳** |

一句话区分：**事实层回答「主人是谁」，日记层回答「我们一起经历过什么」。**

事实层是「无时间的人设档案」——「主人备考公安联考」。它答不了「上周三我们聊到凌晨那次是什么感受」。
长期陪伴要的不是档案，是共同经历。

## 三个能力对应你的三个要求

### 1. 记录日记
- AI 通过 `qq_diary_write` 工具主动写
- 后台定期把对话整理成日记（与事实提炼同构的三重闸门：量够 + 冷却到 + 开关开）
- 写入时**当场脱敏**：`password:`、`sk-xxx`、身份证、银行卡、长 base64 串会被替换成 `[已省略]`

### 2. 记起更久远的事
`qq_diary_recall` 按「关键词 + 标签 + 人物 + 心情 + 时间窗口 + 重要度」检索。

打分是可解释的，没有任何学习参数：

```
score = (重要度 - 3) × 0.6
      + 时间衰减 × 1.2          # 0.5 ^ (天数 / 半衰期30天)
      + 有更正 ? 0.3 : 0
      + log1p(命中加权) × 2.2   # 标题命中×3 > 标签/人物×2.5 > 正文×1
```

**为什么不用向量数据库**：单机、Node 无外部依赖、日记量级在千条以内。
为了 1000 条日记引入 embedding 服务，是拿部署复杂度换几乎测不出的召回提升。
中文检索用「整词 + 字二元组」混合，对「考试」「熬夜」这类短查询已经够用，且完全可预测、可单测。

**顺带一个反直觉的点**：如果查询有关键词，零命中的条目会被**丢弃**，哪怕它很重要、很新。
否则「查考试」会返回一堆因为「近期/重要」而排上来的无关日记。

### 3. 新会话保持记忆和风格
这是日记层最关键、也是事实层做不到的部分。

注入 prompt 时分三段，**不能合并**：

1. **【最近的日记】** —— 维持连续感（「昨天聊到的那个」）
2. **【相关的旧日记】** —— 按本轮用户消息检索，回答「更久远的事」
3. **【说话风格参考】** —— 取高重要度的**原话片段**（`quote` 字段）

第三段是「风格一致」的关键。新会话的模型没有旧会话的上下文，
它需要的是**样板语料**——自己过去怎么说话。这只能由日记里的原话提供，
事实层（第三人称叙述）给不了。

`quote` 字段因此在 `normalizeEntry` 里被原样保留，任何「整理」都会让锚点失效。

## 隐私边界（最重要的一条）

**日记只在主人本人的私聊里注入、读写。**

这与主人长期记忆的规则完全一致，且设了三道闸：

1. 工具层：`qq_diary_*` 检查 key 必须是 `private:<ownerQQ>`，否则直接拒绝，不发请求
2. 服务端：`/api/socialV2/diary` 再查一次 `isOwnerPrivateSession(key)`
3. 注入层：`diaryBlockFor` 只对主人私聊返回内容

**为什么必须三道**：工具层能绕过，服务端才是真正的那道门；
注入层则防住「以后有人改了前两道但忘了这里」。

群聊里主人的日记绝不能被念出来——这是本项目最不能犯的错误。

## 数据与一致性

`state/diary.jsonl`，append-only JSONL。

- 逐行独立解析，坏一行只丢一行（不像 JSON 数组会整库失败）
- 纠错走 `appendCorrection`：原文**永不被改写**，纠正挂在 `corrections` 里
- 上限 5000 条，裁剪时 5 星永不删除
- 加载失败时降级为**只读**，绝不拿内存空库覆盖磁盘

## 配置

`config.json` 的 `diary` 段：

```json
{
  "diary": {
    "enabled": true,
    "minMessages": 15,
    "batchMessages": 30,
    "writeCooldownMs": 3600000,
    "recentDays": 7,
    "injectRecent": 5,
    "injectRecall": 4,
    "injectStyle": 3
  }
}
```

`injectStyle: 0` 可单独关掉风格注入（保留记忆但不注入原话）。

工具开关在 `socialV2.tools.diary`，与 `memory` **分开**：
主人可能想关掉这种带主观叙述的记忆，但不影响轻量记忆。

## HTTP API（控制台/调试）

```
GET  /api/socialV2/diary?key=private:<QQ>&q=联考&limit=20
GET  /api/socialV2/diary?key=private:<QQ>            # 不带 q = 最近 20 条
POST /api/socialV2/diary          { key, token, body, title, mood, tags, quote, importance }
POST /api/socialV2/diary/correct  { key, token, id, text }
```

**没有删除端点**。这是刻意的：一旦允许模型改写/删除人物认知，
一次幻觉就会永久污染它对这个人的记忆。纠错只能追加。

## 已知限制

1. **后台自动整理依赖学习会话可用**。DSH 未就绪时会跳过，不报错（日记是增值能力，不该阻塞聊天）。
2. **检索是词面匹配**。同义词（「联考」vs「公安考试」）不会自动互通。
   若要补，优先加一个同义词表，而不是引入向量库。
3. **注入预算**：`recentMax + recallMax + styleMax` 三段合计约 2-4KB，已由测试锁定上界。
   日记正文很长时按 220 字符截断。
