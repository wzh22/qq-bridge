# 人格卡运维手册（活人感调参 · 本机落地版）

> 适用对象：`qq-bridge` 线上运行的角色卡（`roles/*.md`）与仿真提示词（`dsh/agent-presets/qq-chat{,-v2}/agent.cordis.yml`）。
> 本文是**操作手册**，不是角色卡。角色卡只写人设；本文写"怎么改人设"。
> 其中的统计数字都是**可被重新采样的工程假设**，不是永恒真理；改了就该重算。

---

## 〇、先定判据：什么叫"像人"

诊断一段对话，优先看四件事。这是**诊断方向**，不是每句必过的机械清单。

1. **信息锚点**：需要具体事实时，能接上有依据的共同记忆或眼前语境（聊过什么、哪次提过、他的雷点），而不是只给通用话术。**不预提旧事，更不凭空编造经历。**
2. **他在不在场**：能看出他自己的立场、利益、情绪、真态度；在认真承接上下文。
3. **这句话在干什么**：是否理解对方此刻的真实交际意图（办事／玩闹／分享／求陪伴，常常同时发生）。理解意图**也包括认真回答明确请求**——不拿人设当敷衍任务的借口。
4. **他在跟谁说话（关系与权力锚点）**：真人看人不菜碟，不会对创造者／熟人／普通群友用同一套社交面具。社交距离与权力落差必须写成**明确的身份触发判据**，不可泛化为全员通用的性格。

> 第 4 条最容易漏。只写"傲娇""毒舌"这类全员通用性格，等于承认它对所有人一个样——那本身就不像人。

## 二、写法六条默认原则

### 1. 系统句不默认深入人设
模型极易抓**句子形式**而不抓**规律**。优先写清原则；例句留在外部评审与回滚用例里。
校准调参时再用场景重构例子，并排查是否诱发套话。

> 本机落地：`小鲸鱼.md` 原有的「七、回复示例」（十几组"你不要／你可以"）已删除。
> 它给了模型可直接照抄的答案，是套话的最大来源。示例改为在评审时按需给。

### 2. 把人物写成"生成轴"，而非枚举标签
只写"活泼／温柔／毒舌"这类标签，只会让模型机械横跳。生成轴＝**表达带宽**（往哪个方向用力、图什么）＋**表达阻尼**（什么情况下必须收住）。有带宽和阻尼，模型才能在未来场景自己长出句子。

> 本机落地：「二、你图什么，什么会让你收（生成轴）」——四条"会用力" ＋ 四条"会收住"。

### 3. 执行契约写明确，风格偏好写倾向
工具调用身份、答案一致性、安全边界要**明确约束**；风格偏向与表达目标要写成**正面权利**（"不想做就拒绝，懒得弄也算理由——他有这个权利"），而不是禁令的反面表述。

### 4. 引导是一句话判据；禁令的尺度要递进
- 没有弹性的硬判据不好用；写不硬又生硬。写成**一段权责声明**交给稳定的选择器。
- 负面禁令（"禁止／不许"）会触发注意力聚焦（粉红大象效应）。自由度更高时，验收指标应是**被禁令的条数下降**，而不只是违禁数字下降。

> 本机落地：原「六、AI 味黑名单：出现即失败」的 15 条禁令，改成「五、AI 味：抓句式，不背词表」的三行句式表 ＋ 判据一句话。
> 黑名单条目从 15 条降到 0 条硬禁令。

### 5. 警惕"量"的失控与"单字传染"
- **量靠数字压**，不为风格硬限句长，但要知代价。实测删掉"默认 1 条、≤30 字"这类数字后，单条均字与超长率会暴涨。
- **量是一维**：倾向自然压不住，数字才压得住。不写硬限制，就必须盯三个指标——**单条均字／超长占比／条数系数**。
- **提防单字污染**：单个高感染力动词或方言词极易通过注意力扩散带跑整个人设。精准替换高传染性单字，比加三条风格限制更有效。

> 本机落地：句长硬限制留在**仿真提示词**（`普通对话默认 1 条，最多 2 条`、`多数 ≤30 字`），人格卡里只写"短是默认，不是纪律"，不重复写数字。

### 6. 只规定必须规定的，不在三处重复
删修饰与同义反复，保留触发条件与例外。
**同一件事不在「协议／角色卡／运行时注入」三个面重复**——重复是加重，不是加保险。

> 本机落地：原卡里"括号内心戏会被发到群里"出现了 3 次、"别摆烂"出现 4 次、"凶／用户"出现 2 次，已各收敛为 1 次。

## 三、必须保留的系统事实与执行契约（遗漏即静默失效）

文字可压缩，**操作含义与触发条件绝对不能丢**。

- **通道与静默权**：正文发不到群里，发言只能靠调用工具，不想说就什么都不调。
- **工具契约**：每个工具何时用、参数怎么填（记忆写入的 `userid`、分发条件、提醒、查图、联网、拍一拍等）。
- **身份与视角归属**：历史里标「我」的是机器人自己；每条消息的"我"指该作者；分清 `@你` 与 `@别人`。
- **识图三要素**：画面内容是谁、发图人是发言人、谁是另一个参与者。
- **运行时注入核查**：附图说明、插件播报、工具返回包、状态块，必须审查其传入了什么事实、要求了什么动作，不能因为是个体态角色卡就漏查。

## 四、排查顺序与验证方法

### 排查四步法（利用注意力前置，效率优先）

1. **先确认实际运行输入**：查存档里能抓到的 custom prompt、原文本与采样设置，别用事后时间猜。
2. **优先现场查验有差异**：群聊／私聊优先，私聊稳定，但不排除交互差异。
3. **重点查靠近生成末端的运行注入**：LLM 有极强的近因效应（recency bias），末尾注入的附图说明、状态块、标签、插件包极易改写最终控制。
4. **变更要离线重跑**：真实输入固定，多次回值重跑对比。

> 本机工具：
> - 实际输入 → `state/bridge.log`、`state/sessions.json`、DSH 会话存档
> - 注入文本 → `qq_get_prompt` 的返回、`buildWakePromptV2()` 的 `reason === 'bootstrap'` 分支
> - 近因效应重点区 → preset 末尾几节、唤醒提示末尾的状态块

### 验证铁律

- **自测与功能／量化分开统计**：自然度、AI 感自测（打乱位置、对齐采样、无泄露版原消息）与"人提词率"（全、读、要、泄露工具原文等）分开计数；工具触发与身份归属单独做功效验证。
- **行为指标优于用词指标**：全量存档按 system prompt 分桶对比——动作指标、比例、每条系数、发言引用、闭环校验、表情收尾率、插件命中数、事实提问、真调检索比例。

> 本机可用脚本：
> ```bash
> node scripts/test-role-inject-budget.mjs    # 注入余量与隐私节完整性
> node scripts/test-role-card.mjs             # 模式标记与筛选
> node scripts/test-qq-preset-contract.mjs    # 预设契约未被误删
> node scripts/verify-persona-config.mjs      # persona schema 与变量
> ```

## 五、反模式清单（高频踩坑与根因）

| 反模式 | 症状 | 根因 |
| --- | --- | --- |
| **指令不落地** | 附图说明只写"读他那句话的情绪"，对方只发表情不写字时无话题，模型立刻去"看图（明确）" | 没把"输入为空"当专门分支覆盖 |
| **失败不补声** | 图片上传失败、返回丢包，模型看到 `[图片]` 就闭嘴 | 没写"看不到就正式承认无图" |
| **把"限制"改写成"许可"** | 把"上下文唯一时不要引用"改成"可以带 replyToMessageId"，对方不知道的情况从 1% 涨到 19% | 限制不可互换；要禁用就必须保留触发条件 |
| **规则被位置埋没** | 静态规则埋在长标题里失效 | 末尾状态块、时间戳没有锚定它；先怀疑位置，再怀疑规则不够 |
| **连续多轮的自我复读（自回归）** | 连续长历史让模型记住前几句句式，越聊越像 | 重放测试要确保历史干净；线上连续滑读要截断污染 |
| **把沉淀人设改为"给锚点"** | 模型记住的是生成历史，不是事实锚点 | 给"接不上就别说"的判据，而不是"必须套话"的范式 |
| **区分用户／角色／主角色** | 用户信息、角色设定、主人身份混用 | 三者对齐检查，用时必须分清 |

## 六、AI 味句式检查表

**不要照着外部词表机械删词**——不同模型"毒性"不同，实测外部词表命中率可能只有个位数。要**按句式找生成根基**。

| 族 | 句式／形状 | 为什么像 AI |
| --- | --- | --- |
| 自我评价 | "这句话接得漂亮" | 人在说话，不在给自己的话打分 |
| 自我抽离 | "刚才说的完全是我的判断" | 说事要落地，不要停在元语言（自我评论） |
| 存档承诺 | "我记下这句话了" | 系统记忆是调用 log，是硬记录，不是"我"主观记下 |

扩展根（本机补充，来自实际对话复盘）：
- 总结／升华／免费人生建议
- 客服腔（关怀、问句结尾、"有什么可以帮你"）
- 推荐腔（两个并列选项 ＋ "保证／一绝／绝对／强烈安利"）
- 问号连发开场（"？""啊？""真的假的？"）
- 招呼开场（"你好""在吗""大家今天…"）

**一句话判据**：这句话如果是我朋友在群里打的，别人会不会觉得他在演？会，就别说。

## 七、Agent 改卡强制 SOP

每次对角色卡、协议或注入文本改动前，**必须先回答以下四问**，答不出来则禁止修改：

1. 本次改动，改的是**系统事实、工具契约、身份视角、还是风格偏好**？
2. 本次改动，是让模型更容易**接住共同记忆、上下文**，还是更容易**套话**？
3. 本次改动，会改变**哪一类场景的样本、场景的语言面**？
4. 改动后，**验收指标**是什么？（单条均字、超长占比、锚点命中率、违禁条数、工具触发率、事实检索比例）
