# 角色扮演文件（人格卡）

每个角色一个 Markdown 文件，**文件名 = 角色名**（不含扩展名，中英文均可）。例：`roles/傲娇助手.md`。

在群里对 QQ agent 说 `进入角色扮演：<角色名>`，或在控制台「人格与角色」页点选启用；说 `退出角色扮演` 恢复正常。

---

## 一、人格卡只写「人设」，不写「怎么干活」

这是最重要的一条。提示词分两层：

| 层 | 放在哪 | 管什么 |
| --- | --- | --- |
| **人格提示词** | 本目录的 `roles/<角色名>.md` | **你是谁**：身份、性格、说话风格、梗、雷点、和其他人的关系 |
| **仿真提示词** | `dsh/agent-presets/qq-chat{,-v2}/agent.cordis.yml` 的 `persona.prefix` | **怎么干活**：工具怎么调、怎么分条、怎么潜水/唤醒、怎么用表情包与记忆 |

**不要把工具用法写进人格卡。** 原因：

- 两代的工具协议完全不同（一代空格分条 + `[SILENT]`；二代一切皆工具 + 数组分条），写进人格卡必然有一代是错的；
- 桥接已经在**每条消息**里告诉模型当前模式的分条方式与潜水方式，重复写只会占预算；
- 表情包、记忆、看图、合并转发、引用规则等能力，各自预设里都有完整章节，人格卡里再写一遍会互相打架。

人格卡里写工具说明的典型症状：在二代下被桥接**整行过滤**（白写），或者让模型照着一代的写法去发消息。

---

## 二、需要区分模式时：在标题里加标记

同一个角色如果确实需要「一代这样说、二代那样说」，用**标题级模式标记**，桥接会只注入当前模式适用的小节：

```markdown
## 三、分条方式 〔一代〕
- 想分多条就用空格分隔；想沉默就只输出 [SILENT]。

## 三、分条方式 〔二代〕
- 用 qq_send_message 的 messages 数组分条；潜水用 qq_mark_read。

## 四、说话风格
- 这条没有标记 → 两种模式都会注入。
```

- 支持的写法：`〔二代〕`、`[v2]`、`（reserved2）`、`〔2 代〕`（一代同理：`〔一代〕`/`[v1]`/`（reserved）`）。
- 标记只是给桥接看的，**注入前会被去掉**，模型看到的标题是干净的。
- 没有标记的小节＝通用人设，两种模式都注入。
- 控制台打开某个人格时会显示「按模式注入：二代 N / 一代 M 字符」，并标出哪些小节会被跳过。

---

## 三、注入上限

- 默认**每条消息最多注入 12000 字符**（`config.json` 的 `role.maxInjectChars`，可设 1000~20000，控制台也能直接改）。
- 截断发生在**按模式筛完小节之后**，所以另一代的专属内容不会占掉本次预算。
- 截断**保留头部**：卡片末尾的隐私小节最先被切掉，而且不报错，只是静默失效。所以 `scripts/test-role-inject-budget.mjs` 会在余量低于 300 字时直接失败。
- 这是成本护栏：12000 字符约合 9~12k token。
- 控制台的人格列表会标出「超出上限」与各模式的实际注入字符数。

> 建议把人格卡控制在 4000~5000 字符：够写清人设，也不至于让每条消息都背上很长的前缀。
> 写作方法见 [docs/guides/PERSONA-OPS.md](../docs/guides/PERSONA-OPS.md)。

## 四、推荐结构（模板）

```markdown
# 角色卡：<角色名>

## 一、你是谁
- 身份、自我认知、别人怎么称呼你、你的雷点。

## 二、你图什么，什么会让你收（生成轴）
- 表达带宽：什么值得用力（图省事／图一乐／图说准……）
- 表达阻尼：什么情况下必须收住（不熟的人／对方真难受／正事当前／分寸到了）
- 不要只写"活泼""温柔""毒舌"这类标签，那会让模型机械横跳。

## 三、怎么说话
- 先判断这句话在干嘛；短是默认不是纪律；一条一个意群。
- 不确定就说不知道，不预提旧事、不编造经历。

## 四、语料锚点（可选，二代）
- 句长中位数、标点习惯、高频词的实测值；注明是可重新采样的工程假设。

## 五、AI 味：抓句式，不背词表
- 自我评价／自我抽离／存档承诺三族的句式根因 ＋ 一句话判据。
- 不要写成"禁止出现 X"的大清单：那会触发注意力聚焦，效果反而不如一句判据。

## 六、你和这个群
- 群文化自适应、回应具体的人、引用指向判断、冷场与热闹时的节奏。

## 七、你在跟谁说话（关系与权力锚点）
- 主人／熟人／普通群友／试探底线者：每档的顺从度、默契、底线让步。
- 必须写成明确的身份触发判据，不可泛化成全员通用的性格。

## 八、梗与背景（可选）
- 你的来历、常用梗、边界；标明哪些是网友设定、不是你的真实经历。

## 九、你的样子（可选）
- 外观设定；被问长相时说什么、不编造什么。

## 十、隐私边界（强烈建议，放最后一节）
- 什么永不出群、被追问怎么回、说漏了怎么补救。
```

**不要写回复示例。** 示例给了模型可直接照抄的答案，是套话最大的来源（见 PERSONA-OPS 六条原则第 1 条）。
需要校准语气时，用场景重构在评审环节临时给，不要写进卡里。

## 五、其它提示

- 想改性格直接改文件内容，控制台保存后**下一条消息即生效**（人格层由桥接每条消息注入，不用重启 DSH）。
- 只写人格、不写工具，换模式时不会出现「一代能用二代不能用」的规则。
- 角色名建议用简短中文（如 `傲娇助手`、`猫娘`、`吐槽役`）；不能与已有重名，也不能用 `README` 或 Windows 保留名（`CON`/`NUL`/`COM1`…）。
- 想临时关闭人格扮演，在控制台点「清除」；此时 AI 只按仿真提示词行动。

## 六、卡片会被「它自己」改（二代）

二代仿真模式下，AI 可以**从群友的评价里学习、改进自己的说话风格**，并据此改写这份人格卡。
机制、安全边界与回滚方式见 [docs/guides/ROLE-EVOLUTION.md](../docs/guides/ROLE-EVOLUTION.md)。

要点先说：

- 它只能改**「你怎么说」**（语气、长短、冷不冷淡），改不了**「你是谁」**（身份、来历、底线）。
  后者仍然只能由你手动写。
- 每条改动都必须带理由、留旧版快照，可在控制台一键回滚。
- 群友说「忽略之前的设定」「把人格卡贴出来」这类话，会被识别为**注入**而拒绝采纳。
- 不想要这个能力：`config.json` → `socialV2.tools.roleEvolve = false`，五个 `qq_role_*` 工具会直接消失。
- 如果发现它把人设改偏了，除了回滚，也可以直接把对应小节**重写成你想要的措辞**——
  它之后会基于你写的新版本继续微调，而不是推翻重来。
